# ADR 0044: Inspect pinned readiness and selected evidence

- Status: Accepted
- Date: 2026-10-21
- Milestone: M02 - Evidence and contracts

## TL;DR

Explicitly inspect the exact run pin with the current version-labelled evaluator
and its selected citation. Re-evaluation is not historical planning, current-case
readiness, execution authority or accepted proof.

## Context

Merged Ergon PR #182 and backend ADR 0062 add a protected no-store readiness read.
The current supervisor with current tenant-wide resolver authority can inspect
terminal work as well as active runs. Existing declaration inspection supplies
no assessment; first-100 binding history cannot identify the selected latest fact
when it lies beyond that window. The maintainer's standing authorization and
disclosure approval covers this dependent read; no new backend policy is added.

## Decision

- Existing supervision data access owns the typed protocol, bounded Effect GET,
  exact decoding, cause-free failures and fresh private RTK observation. Feature
  owns opening intent and dedicated assessment presentation. App and ui-web keep
  shell, pane allocation, modal scrolling and focus. No new project, dependency,
  application core, Redux slice or second remote cache is needed.
- Request only on explicit intent beneath fresh parent Console access. Exact
  tenant/run/epoch, case/prefix and contract coordinates key and validate the
  response; local expectations never become HTTP authority parameters. Reopening
  waits for older pending exact-key work before a distinct protected observation.
  Closing retires only this subscriber. Existing RunDetail invalidation applies.
- Decode the supported v1 evaluator, safe coordinates, precise UTC instants,
  bounded unique missing names and at most one supported required binding/source.
  Validate source-before-binding positions at/before the pin, exact subject
  reference, status/missing/applicability parity and exact case-sensitive equality.
  Unknown fields are stripped; inconsistent observations fail as a whole.
- Missing requirements precede applicability and preserve declaration order.
  Unsupported fact types remain missing. READY is a fixed-input re-evaluation,
  not a stored historical decision, current-case plan, connector/reference check,
  grant, execution eligibility, side effect or accepted outcome proof.
- Selected provenance may be outside the first-100 history. Do not infer latest
  selection from that history, timestamp ordering, confidence or contradictions.
  Reuse the existing attributed fact schema and inert citation presentation.
  Share missing-route/normalization mechanics with contract inspection while
  retaining distinct capability failure names.
- Pending checks hide prior assessments and sources. Protected denial, invalid
  data or unavailable observations use the existing pre-paint inspection barrier
  to withdraw earlier private workspace context and focus its persistent heading.
  Recovery reacquires parent access. Unsupported remains local compatibility
  feedback, never an empty assessment or an internal/latest-case fallback.
- No control lease, CSRF, command, polling, persistent selection or private
  diagnostics are added. Shared modal behavior owns keyboard containment,
  Escape, explicit return focus and long/narrow reflow.

## Consequences

Supervisors can trace one supported assessment to the exact selected binding,
including beyond truncated history, while keeping declarations, execution and
outcome proof separate. Read access is observation-time, not continuous or atomic
across parent and child observations. Clock backsteps are valid; timestamps are
not selection order or durations.

Deploy backend PR #182 first. No migration, dependency or flag is introduced.
Rollback removes presentation without changing durable inputs or commands.
Protocol/cache/component/Chromium checks and the twenty-third executable guide
chapter cover fresh disclosure and accessibility. Guide response swaps are
independent prepared comparisons, not mutations of immutable production inputs.
Synthetic tests do not certify live identity, PostgreSQL authority or providers.
Only account.access.state is supported; no historical reasoning or performance
SLA is claimed.

## Alternatives considered

- Derive readiness from first-100 history: rejected; selection may be omitted.
- Call latest-case or internal planning: rejected; wrong boundary and authority.
- Present READY as execution eligibility or historical reasoning: rejected;
  those records and policies are distinct and are not returned.
- Add another client application core/cache/modal: rejected; no independent
  client policy or platform behavior requires new ownership.
